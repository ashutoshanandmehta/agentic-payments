Design proposal · 20 August 2026

The Two-Rail Agent Payment

The user's mandate funds a short-lived virtual card on UPI. The card pays the merchant on card rails. Money rests with the agent for seconds, and the design buys something UPI cannot offer on its own.

Assumed, not argued

  • The local model handles discovery, comparison and checkout reliably.
  • An agent can be added to UPI Circle as a delegate.
  • Holding funds briefly is a licensing question, to be solved with funding.
  • The virtual card runs on Mastercard, so Agent Pay applies to it.

Four parties

User

Grants authority once. Not present at checkout, by design.

Agent

Local LLM in the appliance. Discovers, compares, builds the cart, asks to pay.

Virtual card

A short-lived credential the agent controls. Holds money for seconds, not days.

Merchant

Accepts a card payment. Needs no new integration.

The flow

Time runs downward. The red band is the only interval where money sits with the agent.

The exposure window

Steps 6 to 9 are the only time the user's money is not with the user or the merchant. Every risk this design adds lives inside that band, and every mitigation is about making it shorter: load the exact cart total, pay immediately, sweep on failure.

Step by step

01

The user grants a mandate onceUPI

In their UPI app, with their PIN. Per-transaction limit, monthly limit, expiry date. This is the only moment a human authenticates anything.

per transaction ₹2,000 per month ₹15,000 expires 90 days delegate fridge-01 (agent identity)
02

A virtual card is issued to the agent once

Bound to the mandate. The limits live in the credential, so a compromised agent cannot raise them — it can only spend inside what it was already given.

03

The agent discovers and builds a cart

Local model. Searches, compares, picks. No money is involved and nothing is committed. If the model gets this wrong, it is a bad cart, not a bad payment.

04

The agent signs an intent

A record of the finished cart: items, total, merchant, timestamp. This is what a dispute will later be argued against, so it is signed before any money moves.

cart 9 items, ₹1,240 merchant bigbasket agent fridge-01 signed agent key
05–06

Funds are drawn onto the card UPI

Exactly the cart total, not a round number and not a float. The mandate is checked and consumed here. This is where the money leaves the user.

07

The card pays the merchant card rail

An ordinary card payment as far as the merchant is concerned — no integration, no new SDK. The authorisation carries an Agentic Token and a Verifiable Intent credential, so the issuer can see this was an agent acting under a human mandate.

08–09

Confirm, then sweep

The merchant confirms. Anything left on the card returns to the user immediately. If step 7 failed, the whole amount returns and the cart is abandoned.

Why the second rail is the actual argument

The virtual card looks like an inconvenience — an extra hop, an extra balance to worry about. It is doing something more interesting than that.

UPI has no way to dispute an agent's mistake. NPCI's UDIR system has reason codes for failed, unauthorised and fraudulent transactions. It has no code for "the agent bought the wrong thing." A payment that went exactly where the mandate allowed is, to UPI, a correct payment.

Card rails have 120-day chargebacks, a four-stage dispute lifecycle, and — since March 2026 — Mastercard's Verifiable Intent, which cryptographically ties a transaction to the human-approved mandate it was made under.

So the card is not a wallet. It is a bridge to a rail that has dispute machinery. Fund cheaply on UPI, spend where the recourse lives.

Four things to correct later

  1. Merchant scoping does not survive the hop. On the load, the payee is the card, not the shop — so the mandate can only say "this card", never "this shop". The simulation demonstrates this: a payment reaches a merchant that the same mandate refuses when paid directly. If scoping matters, it has to move onto the card leg.
  2. Liability for agent disputes is not settled. As of mid-2026 neither card network has published a binding chargeback rule for a dispute an agent started, and the one specification that addresses it in writing assigns the loss to the merchant. The recourse this design is built around is real but untested. SECONDARY
  3. Agent Pay is not self-serve. It needs issuer enablement, acquirer integration and network provisioning. There is no sandbox to build against today, and pricing is not published. Fine for a simulation; a real obstacle after that.
  4. UPI Circle may be the wrong primitive. Circle delegates to a person who authenticates biometrically, capped at ₹5,000 per payment and ₹15,000 a month, with no merchant scoping. Reserve Pay is the closer fit, and it is what Pine Labs chose for P3P in June.
